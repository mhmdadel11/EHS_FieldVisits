# EHS FieldVisits - Reports Final V16

تم إصلاح قسم التقارير بالكامل:

- عند فتح `reports.html` يظهر **تقرير الزيارة فقط** مع التقارير السابقة الخاصة بالزيارات.
- زر **إضافة تقرير زيارة** يفتح نموذج الزيارة في نفس القسم ولا ينقل إلى التقرير الشهري.
- بعد الحفظ يظل المستخدم في قسم الزيارات ويظهر التقرير الجديد فورًا في قائمة الزيارات.
- عند الضغط على **تقرير شهري** يظهر **التقارير الشهرية فقط**.
- زر **إضافة تقرير شهري** يفتح نموذج التقرير الشهري في نفس القسم.
- بعد الحفظ يظل المستخدم في قسم التقارير الشهرية ويظهر التقرير الجديد في قائمته.
- نوع التقرير يحدده السيرفر، لذلك لا يمكن حفظ تقرير زيارة داخل قائمة الشهرية أو العكس.
- الملفات المرفقة محفوظة داخل SQL Server في `Reports.FileData`، وليس في LocalStorage أو مساحة تخزين المتصفح.
- تمت إضافة endpoint توافق `/api/reports` لإزالة مشكلة الصفحات القديمة المخزنة في المتصفح.
- تم استبدال النتائج المجهولة (anonymous objects) الخاصة بالتقارير بـ DTOs ثابتة لتجنب خطأ System.Text.Json المتعلق بتعارض `id`.

## مهم جدًا عند التشغيل

1. أغلق أي نسخة قديمة من المشروع تعمل حاليًا.
2. احذف مجلدي `bin` و `obj` من نسخة المشروع القديمة إن وجدا.
3. افتح **هذا المشروع نفسه**: `EHS_FieldVisits_SQLServer.sln` الموجود داخل الملف المضغوط.
4. شغّل المشروع من Visual Studio.
5. افتح `https://localhost:7188/reports.html` أو عنوان HTTPS الذي يظهره Visual Studio.
6. إذا كانت الصفحة القديمة ظاهرة، اعمل Hard Refresh بـ `Ctrl + F5`.
7. للتأكد أن السيرفر الجديد يعمل، افتح `/__ehs_version` ويجب أن يظهر `REPORTS SEPARATED FINAL V16`.

لا تحذف قاعدة البيانات؛ الكود يحافظ على التقارير الموجودة ويضيف/يكمل أعمدة جدول `Reports` عند الحاجة.
